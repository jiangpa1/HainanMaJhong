# 海南麻将运维压测交付

日期：2026-10-12。本包供运维部署候选版本、准备数据和执行压测；此次整理没有访问线上或实际发压。

## 包内目录

- `app/`：JDK 17 可运行的 P2 候选 jar、配置模板、迁移脚本和监控配置。
- `load-test/`：Node.js 22/24 压测入口、配置样例、锁文件、离线 ws 依赖、历史脱敏结果和 CSV。
- `docs/`：P2 迁移与回退、接口、生命周期、监控、计划书和旧压测报告。
- `reports/`：已有两份 PDF 报告。
- `schema-reference/`：旧 SQL 结构参考，**不是生产数据备份，也不包含 P2 新表**。
- `MANIFEST.json`：逐文件大小与 SHA256；交付 zip 的 SHA256 在外部 `SHA256SUMS.txt`。

## 运维执行顺序

1. 校验包和 jar 哈希。确认 SSH、域名、systemd 服务、数据库、Redis、JDK 17 和 Nginx 的实际配置。真实凭据由运维在服务器本地填入 `.env`，不在交付包里。
2. 备份旧 jar、配置、数据库并验证恢复，安排单实例维护窗口。P2 候选版目前只经过本地测试，未在线上迁移或压测。
3. 发布候选 jar，保持双写开启、新读关闭。按 `docs/战绩P2查询与缓存说明.md` 完成 inspect、prepare、分批 backfill、verify、promote；核账通过后才开启新读。迁移 CLI 不需要启动游戏服务。
4. 发压机使用 Node.js 22/24。包内包含 ws 依赖，可直接运行 `node` 命令；需要重装时在 `load-test/` 执行 `pnpm install --frozen-lockfile --ignore-scripts`。运行 `pnpm check` 只做本地自检。
5. 按 `load-test/README.md` 配置独立测试账号和目标地址，先 1 桌 30 秒，再 144→192→224→256 人短测；通过后进行目标档位三轮 30 分钟。
6. 固定代码、机器、带宽、接口口径和初始历史，记录配置和资源采样，回传结果及收尾核对。不要把失败或中止轮次删掉。

服务器保持单实例，管理端口仅通过回环或 SSH 隧道访问。测试会注册账号（仅显式开启时）、建房、产生真实测试战绩；只使用专用账号，不批量删除业务战绩或房间。私有账号文件单独保存，不跟结果回传。

包内 Linux 迁移命令（先由运维设置 `RECORDS_P2_JDBC_URL`、`RECORDS_P2_DB_USER`、`RECORDS_P2_DB_PASSWORD` 环境变量）：

```bash
cd app
java -Dloader.main=hainanMahjong.ops.RecordsP2Migration \
  -cp HainanMaJhong2-1.0-SNAPSHOT.jar \
  org.springframework.boot.loader.PropertiesLauncher inspect
# 依次替换末尾操作为 prepare、backfill 0 100、verify 0 100、promote
```

收尾的数据库/Redis只读核对工具为 `app/ops/inspect-lifecycle.py`，在服务器用 `LIFECYCLE_ENV_FILE=/实际路径/.env python3 ops/inspect-lifecycle.py 本轮房号 ...` 执行；需要 mysql 和 redis-cli 客户端。Nginx gzip 工具随包保留在 `app/ops/nginx/`，先读对应说明再决定是否修改配置。

## 结果口径与未完成项

历史 10/09 基线、10/11 identity/gzip/V2 对照及失败记录用于参考；接口内容、账号历史和网络条件存在差异，不能直接归因于代码。新入口可选择旧 baseline 口径或更严格的 P2 口径，报告同时保留两种判断。

本包混合场景不覆盖浏览器渲染、持续单局详情查询、隔离长历史造数、8 小时连续长测或全部故障场景。上述项目需按计划书另行安排；本包不承诺 256 人已经通过或容量已提高。P2 的收益需要在新读实际开启后测量。

源码主体仍在原仓库，不放进这份运行交付包。开发工具、原始诊断、旧包和本地凭据相关证据已归到仓库的 `.local-archive/`，**该本地归档不可随运维包发送**。必要 SQL 原文件留在 `data/schema-backups/`；生成的 target、node_modules 可重新构建或安装。
