# 4.1 战绩 V2 接口

旧 `/api/records` 接口保留，详情也补上参与者检查，防止借旧接口绕过权限。新接口位于 `/api/v2/records`，沿用 JWT 登录校验，并在读取统计缓存和小局数据之前检查会话参与者。非参与者返回业务码 403，不存在返回 404，参数不合法返回 400；沿用项目 `Result` 包装及 HTTP 200 约定。

## 接口与读取流程

| GET 路径 | 参数 | 返回内容 |
| --- | --- | --- |
| `/api/v2/records` | `pageNum=1`、`pageSize=10`，可选 `readThroughSessionId` | 会话摘要、四家名字、我的分数与名次；最大 20 场/页 |
| `/api/v2/records/byRoom` | `roomId`，六位数字 | 最新会话总览，含稳定 `sessionId` |
| `/api/v2/records/{sessionId}/overview` | 可选 `readThroughRoundNum` | 四家总分、排名、胜局数、最高番，及自己的对应统计 |
| `/api/v2/records/{sessionId}/rounds` | `afterRoundNum=0`、`pageSize=10`，可选 `readThroughRoundNum` | 小局摘要与每局四家分数；最大 50 局/页 |
| `/api/v2/records/{sessionId}/rounds/{roundNum}` | 可选 `readThroughRoundNum` | 单局完整详情，复用旧接口牌型、手牌和结算明细组装 |
| `/api/v2/records/{sessionId}/rounds/new` | 最后已读 `afterRoundNum`、`pageSize=10`，可选 `readThroughRoundNum` | 新增小局摘要；仍分页，不会一次返回所有新增历史 |

1. 列表第一页不传 `readThroughSessionId`，记录返回值，后续页原样传回。新会话不会插入这次翻页列表。会话分数为该请求时的当前值，不承诺跨多个列表请求冻结分数。
2. 打开一场先读总览，取得 `readThroughRoundNum` 和 `version`，第一页 `afterRoundNum=0`。后续分页和单局详情始终传相同截止局号。
3. 小局页返回 `hasMore`、`nextAfterRoundNum`。有下一页时把 `nextAfterRoundNum` 作为下一次 `afterRoundNum`；不要以四家分数行数计算分页。
4. 获取新增结算时调用 `/rounds/new`，携带最后已读局号，首次不传截止点。若新增超过一页，固定首次返回的截止点继续分页。再以此截止点重读总览，确保累计分数和已读明细口径一致。
5. `version` 是 `sessionId:readThroughRoundNum`，表示**结算数据版本**。`latestRoundNum` 是总览请求时最新已提交局号；`status` 为请求时会话状态。截止点 0 表示尚无已结算小局。

顺序键使用现有唯一约束 `(session_id, round_num)`。单次请求使用只读 REPEATABLE READ 事务；跨请求通过截止局号保持结算口径。这个设计依赖 3.1 的“已提交小局不可被重复结算覆盖”，不改变原有 session 创建或再战规则。

## 性能与边界

- 小局先查最多 `pageSize+1` 个 ID，再仅查本页局头及四家分数。摘要查询不读 `win_hand`、`fan_info`、`detail` 等 JSON 大字段；详情只查一局。
- 总览冷读由 SQL 聚合，Java 不加载整场流水。统计缓存最多 512 场，固定有效期 60 秒；相同截止点复用统计，新版本只聚合新增局号范围。读旧截止点、缓存过期或应用重启会回源重算。
- 会话列表复用旧接口的整页批量分数聚合，不逐场读取总览或最高番，避免引入 N+1 查询。
- 缓存只保存数值统计和最高番描述；每次请求先校验参与者。昵称在请求内解析，不放入统计缓存。
- 四家分数缺失或座位不完整时返回 500，避免把被截断的小局展示为完整结算。
- 冷缓存仍会扫描目标会话历史；这里没有宣称已完成 5.1 的索引/执行计划优化或 5.2 的持久化汇总。

## 前端开关

4.2 起默认开启 V2，构建环境变量 `VITE_RECORDS_API_V2=false` 可回退旧接口。大厅战绩与局内战绩均使用总览、每页 10 局摘要以及按需单局详情。翻页替换当前页，不堆积所有历史记录。

PowerShell 示例（在 `frontend` 目录，用本机 Node 20+）：

```powershell
$env:VITE_RECORDS_API_V2 = 'true'
node tools/clean-assets.mjs
node node_modules/vite/bin/vite.js build
```

然后在后端项目目录重新 `mvn package`；只设置后端环境变量不能切换已经构建的前端。关闭/回退时将此构建变量设为 `'false'`，再重新构建前端和打包后端即可。无需数据库迁移。

4.2 已补齐结算提交后的增量刷新、重复请求合并、页面可见性和失败退避，详见同目录《战绩前端按需加载说明》。

## 验证

- `RecordsV2ServiceTest`：10、100、1,000 局模拟会话，分页四家齐全、与旧接口分数和详情一致、响应体有界；并发新增后的截止点与增量统计；缓存命中前鉴权；参数硬上限与空会话。
- `frontend/tools/check-records-v2.mjs`：实际挂载 Vue 组件，验证开关、首屏不读大字段、详情按需请求、前后翻页、固定截止点、失败重试。
- `RecordsV2SqlIT`：可选 MySQL 实库测试，使用连接级临时表，覆盖真实 Mapper SQL、JSON 列和上述三种历史长度。普通单测默认不连接 MySQL。

实库测试需要数据库用户拥有创建临时表权限，先设置 `RECORDS_TEST_MYSQL_PASSWORD`（不要把真实密码写入提交或命令参数），然后运行：

```powershell
mvn '-Dtest=RecordsV2SqlIT' '-Drecords.mysql.url=jdbc:mysql://127.0.0.1:13307/records_test' '-Drecords.mysql.user=root' test
```

该测试不会创建或更改持久化业务表；连接关闭后临时表消失。
