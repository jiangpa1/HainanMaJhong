# 4.2 战绩前端按需加载

4.2 默认启用 4.1 的 V2 接口。大厅战绩和局内战绩共用分页组件：先显示总览与第一页（每页 10 局），翻页仅替换当前页，点“查看详情”才请求该局的手牌、牌型及结算大字段。无需数据库迁移。

## 已提交的小局如何显示

`hu`、`end` 等牌局展示通知可能先于数据库提交，因此不作为战绩刷新依据。服务端在 `RoundPersister.saveHand` 的事务调用成功返回后，才在 `coins` 消息中添加 `sessionId` 和 `committedRoundNum`。保存失败时不会广播这个提交标记。

前端收到提交标记后：

1. 失效该会话的浏览器快照缓存；相同/更旧小局通知不重复刷新。
2. 用上次总览的截止局号读取一页 `/rounds/new`，最多 10 局，不循环追拉未显示的历史。
3. 按增量接口返回的 `readThroughRoundNum` 重新读取总览。
4. 当前末页不足 10 局时合并新增摘要；已满或正在查看历史页时更新版本及翻页状态。其余小局仍通过下一页读取。

总览和明细使用同一截止点。通知落在总览请求与组件挂载之间时，会记住已提交版本并在挂载时补读，避免漏掉刚结束的小局。已有详情仍属于不可变的已结算小局。

本次没有更改会话划分、再战或计分规则。后端总览仍沿用 4.1 的增量统计缓存；它按截止点缓存不可变统计，不必删除旧版本的计算基线。

## 重复动作、可见性与失败

- 相同 API 请求共享在途 Promise，重复打开弹窗不再由点击函数和 watch 各发一遍请求。
- 只缓存带明确截止点的小局页和单局详情：最多 128 项，30 秒寿命。键包含当前登录凭据及请求参数，退出登录清空缓存。总览和无截止点的增量查询不缓存。
- 缓存失效后，已在途的旧结果不能重新填回缓存；切换房间/会话、返回或卸载后，旧任务响应不能覆盖新页面。
- 隐藏标签页暂停后续请求和重试；返回可见时恢复未完成任务，并对当前进行中的会话补读一次增量。增量返回时如果页面已隐藏，也不会继续发总览请求。
- 关闭局内战绩弹窗取消其后续任务和监听。已发出的请求可以完成，但其结果会被丢弃，不继续刷新。
- 网络/服务端临时失败最多自动重试 4 次，间隔 0.5、1、2、4 秒。耗尽后停止，可由用户点击“重试”。400、401、403、404 等错误不进入这类循环；登录续期仍由现有认证封装处理。
- 没有增加固定周期轮询。“检查新小局”可手动补读；WebSocket 重连和恢复页面可见时也会补读，避免漏掉离线期间的结算。

## 发布与回退

本次 JAR 的前端默认启用 V2；后端与前端一起部署即可使用新界面。新的后端 `coins` 标记与旧前端兼容，但旧后端没有提交标记，无法提供自动结算刷新，因此应部署完整的新 JAR。

需要回退旧战绩界面时，在前端构建前设置：

```powershell
$env:VITE_RECORDS_API_V2 = 'false'
node tools/clean-assets.mjs
node node_modules/vite/bin/vite.js build
```

随后重新打包后端。恢复 V2 时清除此构建变量，或设为 `'true'`，再重新构建、打包。只修改服务器环境变量无法改变已构建的前端开关。

## 验证方式

`node tools/check-records-v2.mjs` 验证基本分页和按需展开。

`node tools/check-record-refresh.mjs` 真正挂载 Vue 组件并驱动 Pinia 的 `coins` 消息，验证提交后增量、同版本总览、末页合并、请求合并、详情缓存、隐藏暂停与恢复、隐藏时不继续读取总览、挂载竞态、最多四次退避重试、关闭弹窗清理、旧响应隔离和失效后的缓存回填保护。

`node tools/smoke.mjs` 显式关闭 V2，保留旧接口回退路径的完整冒烟验证。常规 Java 回归继续覆盖房间生命周期、持久化及管理端口隔离。
