## 2. 压测：把原始尝试、逻辑请求和成功延迟拆开

配置新增 `formalReadRetries`（默认 **0**）与 `preparationReadRetries`（默认 4）；runner 显式传递，避免环境变量被清除后偷偷回到旧默认。写请求仍不自动重放。

| 输出 | 含义 |
|---|---|
| `measurementVersion=3`、`retryPolicy` | 固定本轮测量版本及重试预算 |
| `http.sent/completed/rateLimited/failed` | 逻辑请求及最终结果，保留旧字段意义 |
| `http.rawAttempts/rawRateLimited` | 正式查询实际尝试与全部 429，包含中间被重试的拒绝 |
| `httpAttempts` | 全局正式查询与准备/收尾分开的尝试、完成、拒绝计数 |
| endpoint `logicalTiming` / 兼容 `timing` | 整个逻辑请求耗时，包含认证刷新等待、重试与退避 |
| `attemptTiming` / `successAttemptTiming` | 单次 HTTP 尝试，以及成功尝试的网络端到端耗时；不含退避睡眠 |
| endpoint `retryWaitMs`、`networkMs` | 累计退避等待与累计尝试耗时 |
| `acceptedServerLatency.routes` | 同一正式窗口成功响应直方图差分：count、mean、近似 P95/P99 |

服务端快照只读 `metricsUrl`，前后核对进程启动时间、计数器与桶布局；指标缺失或重启则标记不可用，不能填 0。服务端值涵盖该窗口其它客户端，起点位于应用过滤器，可能漏掉 Nginx/Tomcat 之前的排队。因此应同时看成功尝试的客户端分位。直方图分位是桶内插值估计，不是逐条请求精确排序。

`Retry-After` 支持秒数与 HTTP 日期；超过单次 60 秒等待预算时放弃重试，保留 429，不提前重发。原始响应字节把中间尝试一起纳入。旧结果不重新解释，旧版本的最终 0 个 429 不能当作原始 0 次拒绝。

## 3. 有意超载使用独立判据

新增 `acceptanceProfile="overload"`，必须配置 metricsUrl，使用固定速率窗口。该模式不会因预期 429 或退避导致的逻辑耗时单独中止，但仍保留资源护栏、真实错误、跳过、协议和收尾检查。

通过条件包括：实际观察到拒绝；无非预期失败、无跳过；成功客户端尝试和服务端处理均 P95≤500 ms、P99≤2 s（各相关端点至少 100 样本）；对局/账目/广播/收尾正常。拒绝仍计入原始与最终计数，不改记为成功。

普通 baseline/p2 的错误率和逻辑耗时门槛保留；超载模式通过只能说明“本轮拒绝期间成功请求延迟达标”，不能解释为人数容量提升。升降载分开正式窗口，避免把恢复期好数据稀释超载期分位。

## 5. 冷启动与收尾

工具新增 `roomBatchSize`、`roomBatchDelayMs` 与 `rateSteps`。生成的冷启动配置每批 1 房、批间 1.5 秒，查询按 0.5→1.25→2.5 GET/s/桌渐进。它要在新进程单独执行，建房阶段 CPU 与耗时也必须留档；不能把逐步建房的预热成本藏在正式窗口外。

场次结束存在两个可修的薄弱点，已补：

- 服务端 `disbandSession` 事务内条件更新；0 行更新时校验场次确已结束，提交后失效 P2 缓存。房间清理对该幂等操作最多重试 3 次，最终失败输出 room/session/generation 日志及低基数计数器，触发告警；数据库故障时继续清理线程。这里没有持久化补偿队列，最终失败仍需人工修复。
- 工具原先把**较早读取的一份列表 row**作为最终 `sessionEnded`，即使后面的逐人列表检查已看到结束，也可能保留旧结论。现在记录初次和末次结束状态、时间与 HTTP 状态，并以末次独立读取核验；其它逐人检查错误仍导致失败，不用额外读取抹掉它们。

以上能改善幂等、可见性与取证，但**没有复现并证明历史那一房异常的根因已修复**。需用新包对照初末状态及服务端日志，历史失败仍保留。
