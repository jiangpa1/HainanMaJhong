# 房间生命周期修复说明

日期：2026-10-10。对应并发提升计划书 3.1；本次为本地代码改造，尚未部署线上。

## 行为与实现

- `CLOSED` 是永久终态，`BETWEEN` 仍表示合法局间状态。关闭先置 `stop`，后续启动、快照和广播拒绝关闭房间。
- 每次创建生成 UUID `generation`，恢复沿用原值；快照在房间锁内捕获状态并递增 `version`，Redis 写入在锁外执行。
- `room:{code}` 继续存 JSON，TTL 30 分钟。新增 `room:lifecycle:{code}` 哈希记录 generation、version、session、closed，TTL 24 小时。
- 创建通过原子脚本认领房间码。保存脚本校验代际、版本、会话和关闭状态；关闭脚本原子标记关闭并删除快照。旧任务不能删掉或覆盖同码新房间。
- 保存不能创建不存在的生命周期记录，因此关闭保护过期后，迟到任务也不能重新写入。关闭异常最多重试三次，保留错误日志和本进程关闭记录。
- 恢复校验成员、座位、房主、数据库会话结束状态、房间码及四人座位归属，再以原始 JSON 和保护记录做 CAS。注册表防止重复恢复和覆盖其他房间的用户绑定。
- 旧 JSON 没有 generation 时，以原始 JSON 生成确定性 legacy 标识，在完成同样的业务检查后原子认领；后续保存升级格式。
- 游戏连接绑定 generation；旧连接的动作不能送入复用同一房间码的新房间。注销使用实例比较，旧实例不能注销新实例。
- 创建会话、结算提交与关闭在同一房间锁内确定顺序；不在锁内等待引擎线程结束。数据库结算事务锁定会话行，拒绝结束会话的写入；重复小局直接返回已有记录，不覆盖已提交流水。结束 SQL 不重复改写结束时间。
- 关闭取消当前询问和调度器、打断引擎线程，并清除恢复种子。取消与注册询问并发时，不再留下等待或超时任务。
- 保存庄流的实际下一局庄家及完成标记，防止在结算边界重启后错庄或额外开局；合法 BETWEEN 房间仍能恢复并继续再战。

## 验证

执行 Java 17 / Maven 离线测试，Redis 原子脚本测试显式连接本机隔离实例，不加载项目连接配置；测试使用随机专用 key，不执行 FLUSHDB。

```powershell
mvn -o -Dlifecycle.redis.port=16379 test
```

已通过 64 项测试，零失败、零错误，包括：

- 真实 Redis 上 30 轮并发保存/关闭，最终无快照残留。
- 乱序保存、重复版本、会话变化、关闭保护过期、房间码复用、旧代关闭和旧快照恢复。
- 延迟保存与关闭并发、三次关闭失败、重复销毁、成员非法、会话结束、成员归属冲突、同时恢复。
- 合法局间恢复、旧格式升级、完成边界恢复、下一庄家保存和旧连接代际检查。
- 取消询问后引擎解除等待、调度器结束；原有真人出牌、锁和 400 把机器人回归。

## 部署与验证范围

不需要新增数据库字段或清空 Redis。Redis 权限需要支持 EVAL/EVALSHA 及脚本内的 GET、SET、HGET、HSET、EXISTS、DEL、PEXPIRE。旧程序仍会无条件写快照，不能让旧版本与新版本同时操作活动房间；应按计划书停止接新桌、等待活动桌结束，再整体切换。

本次未连接项目 MySQL，数据库相关行为经过单元测试，真实 MySQL 行锁、事务回滚与重启恢复仍需在隔离测试环境验证。已有 `RoundPersistenceServiceIT` 不属于 Maven 默认单元测试范围。

如果数据库已提交小局而 Redis 仍是该小局的旧快照，恢复会拒绝继续，避免重放导致金币重复计算；本次没有实现从数据库自动重建这类落后快照。若 Redis 关闭保护和数据库结束写入同时失败，且进程随后重启，无法仅凭进程内记录保证持久关闭，需依据日志核对修复。上述故障不能宣称为任意重启无损。

监控面板、线上故障演练和容量压测属于后续验证；本次测试结果不代表已经提高线上并发容量。
