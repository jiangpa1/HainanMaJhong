# 工程交付与数据规范

## 从源码构建，不再向旧 jar 注入 class

需要 JDK 17（包括 javac）、Maven、Node.js 22 或更新版本及 pnpm。避免 PATH 指向 Java 8 或 Node 14。前端依赖按锁文件安装，完整构建命令：

```powershell
cd HainanMaJhong/frontend
pnpm install --frozen-lockfile --ignore-scripts
cd ..
./ops/build-release.ps1 -JavaHome '<JDK17目录>' -Maven '<mvn.cmd路径>'
```

脚本先清理并重建前端 assets，再运行 `mvn clean package -DskipTests`；测试源码参与编译，测试不执行。清理目标须在项目内，拒绝重定向的 target/assets。`static/img`、`music`、`apk` 是源素材，不清空整个 static。当前保留仓库已有的静态构建产物跟踪方式，前端重建后的 hash 文件增删是正常差异。

输出位于 `target/`：完整 Spring Boot jar、`source-manifest.json` 与 `build-report.json`。脚本比对编译产生的所有 class 是否进入 jar，专门检查曾漏包的 `$Encoded.class` 和前端入口。报告记录 jar SHA256、源码清单 SHA256、commit 和工作区是否有未提交改动。

这建立的是完整源码构建与内容追溯，不保证两次构建二进制逐字节一致。若依赖缓存缺失，安装/构建需要联网；锁文件与本次工具版本见构建核验。交付时使用完整 jar，连同外置配置变更说明和上一完整包，禁止手工抽几个 class 覆盖旧包。

## 公开与私有目录

| 目录 | 内容与规则 |
|---|---|
| `HainanMaJhong/docs/` | 面向代码读者的设计、实施、方法论和实测报告；不放凭据或真实账号明细 |
| `docs/performance/*.mjs`、`config.example.json`、`accounts.example.json` | 参数化、可阅读的公开发压工具与占位配置；私有便利脚本不作为唯一复现入口 |
| `docs/performance/public/` | 人工复核的标量结果与来源文档；不保留账号、房间、请求正文或全量指标标签 |
| 已有 `results-*` 公开白名单 | 仅保留当前允许的图表/汇总，历史路径不改，便于旧报告追溯 |
| `docs/performance/runs/`、其余 `results-*` | 原始运行结果、采样和配置，默认忽略；每轮新目录，不覆盖失败轮 |
| `docs/performance/private/`、`config.local.json` | 真实账号、目标、凭据和本机运维脚本，忽略；只在受控环境流转 |
| `docs/performance/history/` | 历史派生 JSON/JSONL 默认忽略，索引 CSV 与说明可公开；脱敏过不等于自动适合公开 |
| `.local-archive/`、`data/schema-backups/*.sql` | 本地证据、旧备份，默认不入库；当前表结构以建表/迁移源码为准 |
| `target/`、`release/`、`deliverables/*.zip` | 可生成产物，默认忽略；旧交付包不代表最新源码构建 |

`.gitignore` 只影响未跟踪文件，不能移除已经提交的秘密。本次不执行 `git rm --cached`、批量暂存、提交或历史重写，保留已有改动与删除供审阅。对外发布前若发现已跟踪敏感文件，应单独处理并按情况轮换凭据。

可运行 `node HainanMaJhong/ops/audit-public-files.mjs` 做只读初筛：检查已跟踪及未忽略候选文本中的私有路径、JWT、私钥标记和配置明文凭据，只输出路径、行号与类别。它不扫描 Git 历史或二进制，也不能代替人工检查账号标识、主机地址与 SQL 数据；没有命中不代表完整安全认证。

## 一轮证据至少保留什么

使用独立 run id，私有目录保存配置、jar hash、指标、原始结果、准备/预热/正式/收尾时间及停止原因。公开只导出需要解释结论的字段，附来源报告、原判定与不可比因素；缺失项留空。不得将收尾失败、人工停止、保护停止改写为通过。

`public/key-results.csv` 是报告中的关键行摘录，不是所有实验清单，也不是直接重新计算的原始结果。`public/write-manifest.mjs` 为公开文件及其来源报告生成 SHA256，便于发现后续修改；hash 只证明内容对应，不证明实验真实或结论正确。

## 变更收敛顺序

当前已有大量跨主题修改。本次保留它们，不替用户自动提交。建议审阅后按：房间/P2 → 推送协议 → HTTP 准入 → 压测工具 → 文档与交付规范，分别提交；每次提交都以完整构建为基线。旧测试与结果应归属被测包，不因新 commit 自动成为新版本的验收结果。

本次仅执行构建、语法与包内容核对；没有运行单元测试、端到端测试或线上压测。因此不得将构建成功写成运行时、业务或性能验收通过。
